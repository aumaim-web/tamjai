# ร้านตามใจ — ระบบจัดการร้านอาหาร

มีแค่ 2 ส่วน: **หน้าเว็บ** (HTML/JS ในโฟลเดอร์ `public/`) และ **ฐานข้อมูล Firebase** (Firestore + Authentication)
ไม่มีเซิร์ฟเวอร์ ไม่ต้องรัน `npm` หรือ `start.bat` — หน้าเว็บคุยกับ Firebase โดยตรง และขึ้นออนไลน์ด้วย Firebase Hosting

โปรเจกต์ Firebase: `tamjaifood230` → https://tamjaifood230.web.app

## ตั้งค่าครั้งแรก

1. Firebase Console → **Authentication** → **Get started** → แท็บ **Sign-in method** → เปิด **Email/Password**
   (ต้องเปิด *Enable create (sign-up)* ไว้ในแท็บ Settings → User actions เพราะลูกค้าสมัครสมาชิกเองด้วยอีเมลอะไรก็ได้ — บัญชีลูกค้าไม่ได้สิทธิ์ดูข้อมูลร้าน)
2. สร้างบัญชีพนักงาน 4 บัญชี แยกตามหน้าที่ (owner / finance / stock / kitchen) พร้อมรหัสผ่านสุ่ม:
   ```
   node tools/create-users.js
   ```
   รหัสผ่านจะอยู่ในไฟล์ `initial-passwords.txt` (ไม่แสดงบนหน้าจอ) — เก็บไว้แล้วลบไฟล์ทิ้ง หรือเปลี่ยนรหัสเองใน Firebase Console → Authentication
   ต้องมี `serviceAccountKey.json` (Console → Project settings → Service accounts → Generate new private key) **ห้ามแชร์ไฟล์นี้ และไม่อยู่ใน GitHub** — ดูรูปแบบได้จาก `serviceAccountKey.example.json` (ไฟล์ตัวอย่าง ไม่มีค่าจริง)
3. ปล่อยกฎความปลอดภัยและหน้าเว็บขึ้นออนไลน์:
   ```
   firebase deploy --only firestore:rules,hosting
   ```
4. เปิด https://tamjaifood230.web.app แล้วล็อกอินเป็น `owner` ถ้าฐานข้อมูลยังว่าง กดปุ่ม **รีเซ็ตเป็นข้อมูลตัวอย่าง** ที่แถบล่าง

แก้หน้าเว็บแล้วอยากอัปเดต: ดับเบิลคลิก `deploy.bat` (หรือ `firebase deploy --only hosting,firestore:rules`)

## ใช้ที่หน้างาน (ไม่ต้องติดตั้งอะไร)

ระบบอยู่ออนไลน์แล้ว เปิด **https://tamjaifood230.web.app** ในเบราว์เซอร์เครื่องไหนก็ได้ที่มีอินเทอร์เน็ต
- ดับเบิลคลิก `เปิดระบบร้านตามใจ.url` เพื่อเปิดเว็บทันที
- `QR-เว็บร้านตามใจ.svg` ให้ลูกค้า/ผู้ชมสแกนด้วยมือถือ (ส่วน QR ประจำโต๊ะ พิมพ์จากหน้า "จัดการโต๊ะ")

## ใช้บนเครื่องอื่น (แก้โค้ด + deploy)

1. ก๊อปโฟลเดอร์ `tamjai-split` ไปเครื่องใหม่ — ไม่ต้องก๊อป `node_modules`, `.firebase`, `tamjai.db*`
   และ **ไม่ต้องก๊อป `serviceAccountKey.json`** ถ้าไม่ได้ใช้ `tools/create-users.js` (ไฟล์นี้เป็นความลับ)
2. ติดตั้ง [Node.js](https://nodejs.org) เวอร์ชัน LTS (20 ขึ้นไป — อย่างอื่นไม่ต้องติดตั้ง)
3. **ดูหน้าเว็บในเครื่อง:** ดับเบิลคลิก `run-local.bat` → เปิด http://localhost:5000 ให้เอง แก้โค้ดแล้วกดรีเฟรชดูผลได้ทันที
   (ใช้ฐานข้อมูลจริง — สิ่งที่ทำในหน้าเว็บมีผลกับร้านจริง)
4. **ปล่อยขึ้นเว็บ:** ดับเบิลคลิก `deploy.bat` → ครั้งแรกจะดาวน์โหลด Firebase CLI ให้เองและเปิดเบราว์เซอร์ให้ล็อกอินบัญชี Google
   บัญชีนั้นต้องมีสิทธิ์ในโปรเจกต์: เจ้าของโปรเจกต์เพิ่มได้ที่ Firebase Console → Project settings → Users and permissions
   ลองก่อนโดยไม่ปล่อยจริง: เปิด Command Prompt ในโฟลเดอร์นี้แล้วพิมพ์ `deploy.bat --dry-run`
5. (ไม่บ่อย) สร้าง/รีเซ็ตบัญชีพนักงานด้วย `tools/create-users.js`: วาง `serviceAccountKey.json` ในโฟลเดอร์ แล้วรัน `npm.cmd install` ครั้งแรกก่อน
   (เพิ่มพนักงานใหม่ทำได้จากหน้าเว็บ "ผู้ใช้และสิทธิ์" อยู่แล้ว ไม่จำเป็นต้องใช้สคริปต์นี้)

ถ้า PowerShell ขึ้น "running scripts is disabled" ให้ใช้ดับเบิลคลิกไฟล์ .bat แทน หรือพิมพ์ `firebase.cmd` / `npm.cmd` แทน `firebase` / `npm`

## บทบาทและสิทธิ์

เข้าสู่ระบบด้วยปุ่ม **เข้าสู่ระบบ** ที่แถบบน (พนักงานพิมพ์แค่ `owner` / `finance` / `stock` / `kitchen` ก็ได้ ไม่ต้องพิมพ์อีเมลเต็ม)

| อีเมล | บทบาท | ใช้ได้ |
|---|---|---|
| owner@tamjaifood230.web.app | เจ้าของร้าน | ทุกอย่าง รวมถึงจัดการเมนู/พนักงาน/ลบวัตถุดิบ |
| finance@tamjaifood230.web.app | ฝ่ายการเงิน | ขายหน้าร้าน, คำสั่งซื้อ, รับชำระ, ลูกค้า, รายงาน |
| stock@tamjaifood230.web.app | ฝ่ายคลังสินค้า | สต็อก, ดู/อัปเดตคำสั่งซื้อ |
| kitchen@tamjaifood230.web.app | ฝ่ายรับออเดอร์ | หน้า "ครัว / รับออเดอร์": ออเดอร์ลูกค้าขึ้นทันที → ทำอาหาร → กด "ทำเสร็จแล้ว" (ไม่เห็นข้อมูลลูกค้า บิล และเงิน) |
| อีเมลอะไรก็ได้ (สมัครเองในหน้าเว็บ) | ลูกค้า | ดูเมนู และส่งออเดอร์ (ชำระที่เคาน์เตอร์) — ออเดอร์จะแสดงอีเมลลูกค้าให้พนักงานเห็น |
| (ไม่ล็อกอิน) | ลูกค้าทั่วไป | สั่งอาหารได้เหมือนกัน แต่ไม่มีอีเมลแนบ |

อีเมลโดเมน `@tamjaifood230.web.app` สงวนไว้สำหรับพนักงาน ลูกค้าสมัครด้วยโดเมนนี้ไม่ได้ ถ้าลืมรหัสผ่านพนักงาน สุ่มใหม่ได้ด้วย `node tools/create-users.js --reset-passwords`

**ออเดอร์ของลูกค้า:** เข้าคิวก่อน (`guestOrders`) แล้วฝ่ายรับออเดอร์ (kitchen) หรือแคชเชียร์ (owner/finance) ที่เปิดหน้าจออยู่จะรับให้อัตโนมัติ — ตอนรับจึงจะตัดสต็อก ออกเลขออเดอร์ และออกบิล "รอชำระ" ถ้าไม่มีใครเปิดหน้าจอ ออเดอร์จะรออยู่ในคิว
ลูกค้าเห็นสถานะในหน้า "ติดตามออเดอร์" แบบสด: **รอร้านรับออเดอร์ → กำลังทำอาหาร → ทำเสร็จแล้ว** (ครัวกด "ทำเสร็จแล้ว" แล้วเปลี่ยนทันที)
ถ้าวัตถุดิบไม่พอตอนรับ ออเดอร์จะถูกปฏิเสธและแจ้งเตือนที่หน้าจอผู้รับ (ลูกค้าเห็นเหตุผลในหน้า "ติดตามออเดอร์")

**รูปเมนู:** ลูกค้าเห็นรูปอาหารในหน้าสั่ง เจ้าของร้านเพิ่ม/เปลี่ยน/ลบรูปได้ที่หน้า "จัดการเมนู" (ปุ่ม เพิ่มรูป / เปลี่ยนรูป) ระบบย่อรูปให้อัตโนมัติและเก็บไว้กับเมนู (ข้อมูลตัวอย่างจากปุ่มรีเซ็ตไม่มีรูป ต้องอัปโหลดเอง) ควรใช้รูปที่ถ่ายเองหรือได้รับอนุญาต

**QR Code โต๊ะ:** เจ้าของร้านเปิดหน้า "จัดการโต๊ะ" → กด "QR ทุกโต๊ะ" → พิมพ์ไปวางที่โต๊ะ (ถ้าเปลี่ยนชื่อโต๊ะต้องพิมพ์ QR ใหม่) ถ้ายังไม่มีโต๊ะ กด "สร้างโต๊ะ 1–12"

  js/db/*.js                 ชั้นข้อมูล (คุยกับ Firebase) แยกเป็นส่วนๆ โหลดตามลำดับใน index.html:
                               core (ตั้งค่า/ตรวจสิทธิ์/Audit) · session (ล็อกอินค้าง) · loaders (โหลดข้อมูล)

                               seed (ข้อมูลตัวอย่าง/รีเซ็ต) · router (ตัวลงทะเบียนเส้นทาง)
                               routes-auth / people / stock / menu / tables / orders / reports / users (เส้นทางแต่ละหมวด)
                               dispatch (dbApi ที่หน้าจอเรียก)
  js/api.js                  โหลดข้อมูลใหม่, หน้าต่างเข้าสู่ระบบ, รับออเดอร์ลูกค้า
  js/seed-data.js            ข้อมูลตัวอย่างสำหรับปุ่มรีเซ็ต
  js/utils.js, config.js, state.js, modal.js, components.js, app.js, views/*.js
firestore.rules              กฎความปลอดภัยของฐานข้อมูล (สำคัญที่สุด — ดูด้านล่าง)
firebase.json, .firebaserc   ตั้งค่า Hosting / Emulator / โปรเจกต์
tools/create-users.js        สร้างบัญชีเข้าสู่ระบบ + กำหนดบทบาท

ไฟล์ JS ฝั่งหน้าจอเป็นสคริปต์ธรรมดา (ไม่ใช่ module) ใช้ตัวแปรร่วมกัน จึงต้องโหลดตามลำดับใน `index.html`

## ความปลอดภัย (อ่านก่อนแก้ firestore.rules)

เพราะไม่มีเซิร์ฟเวอร์คั่น **กฎใน `firestore.rules` คือด่านเดียวที่กั้นข้อมูลร้าน** โค้ดในหน้าเว็บใครก็แก้หรือข้ามได้ กฎที่ตั้งไว้:
- ลูกค้าอ่านได้แค่เมนูกับจำนวนวัตถุดิบ เขียนได้แค่ส่งออเดอร์เข้าคิว (รูปแบบถูกตรวจ) แก้ราคา/สต็อกเองไม่ได้
- สต็อกติดลบไม่ได้, ออเดอร์แก้ได้เฉพาะสถานะ (กำลังทำ → เสิร์ฟแล้ว, ยกเลิก), แก้บทบาทตัวเองไม่ได้
- ข้อมูลลูกค้า/พนักงาน/บิล อ่านได้เฉพาะพนักงานตามบทบาท
- ฝ่ายรับออเดอร์: สร้างได้เฉพาะออเดอร์ "กำลังทำ" ของลูกค้าทั่วไป และบิล "รอชำระ" (ตอนรับจากคิว) — อ่านบิล/ข้อมูลสมาชิกไม่ได้ รับเงิน/ยกเลิกไม่ได้

ข้อจำกัดที่ต้องรู้: กฎตรวจ "ราคาที่บันทึกในออเดอร์ถูกต้องไหม" และ "ตัดสต็อกตรงสูตรไหม" ไม่ได้ ดังนั้นผู้ที่ล็อกอินเป็น owner/finance ทำได้ทุกอย่างที่ฝ่ายนั้นมีสิทธิ์ ควรแจกรหัสผ่านเฉพาะคนที่ไว้ใจ

## ทดลองในเครื่อง (ไม่แตะข้อมูลจริง)

ต้องมี Java และ `npm i -g firebase-tools`
```
firebase emulators:start --only auth,firestore,hosting --project tamjaifood230
```
ตั้งตัวแปร `FIRESTORE_EMULATOR_HOST=127.0.0.1:8080` และ `FIREBASE_AUTH_EMULATOR_HOST=127.0.0.1:9099` แล้วรัน `node tools/create-users.js` เพื่อสร้างบัญชีทดลอง จากนั้นเปิด http://127.0.0.1:5000/?emulator (ต่อท้าย `?emulator` เพื่อให้หน้าเว็บใช้ฐานข้อมูลทดลอง) ดูข้อมูลที่ http://127.0.0.1:4000

## Collection ใน Firestore

| Collection | เก็บอะไร |
|---|---|
| users | บทบาทของบัญชี (id = uid ของ Firebase Authentication) |
| customers | ข้อมูลลูกค้า + แต้มสะสม (1 แต้มทุก ฿25) |
| employees | ข้อมูลพนักงาน |
| stock | วัตถุดิบ จำนวนคงเหลือ จำนวนขั้นต่ำ |
| menu | เมนูอาหาร + สูตรในฟิลด์ `recipe` |
| orders | คำสั่งซื้อ (id = เลขออเดอร์) + รายการอาหารในฟิลด์ `items` |
| payments | การชำระเงิน (1 ออเดอร์ = 1 บิล) |
| meta/counters | เลขออเดอร์/เลขบิลล่าสุด |
| guestOrders | ออเดอร์ที่ลูกค้าส่งเอง รอแคชเชียร์รับ (id = รหัสคิว) |
| tables | โต๊ะ (ชื่อ) — ลูกค้าอ่านได้เพื่อตรวจ QR |
| track | สถานะออเดอร์ให้ลูกค้าติดตามด้วยรหัสคิว (อ่านรายตัวได้ ดูทั้งหมดไม่ได้) |

## กติกาทางธุรกิจ

- ราคาอาหารอ่านจากฐานข้อมูลตอนบันทึกออเดอร์เสมอ ไม่เชื่อราคาที่หน้าจอส่งมา
- สร้างออเดอร์ = ตรวจวัตถุดิบ → ตัดสต็อก → บันทึกออเดอร์และบิล ใน transaction เดียว ถ้าวัตถุดิบไม่พอจะไม่บันทึกอะไรเลย
- ยกเลิกได้เฉพาะออเดอร์ที่ยังไม่ชำระ ต้องใส่เหตุผล และคืนวัตถุดิบเข้าสต็อก — เจ้าของร้านยกเลิกได้เลย ฝ่ายการเงินต้องส่งคำขอให้เจ้าของร้านอนุมัติ
- เมนูที่ตั้ง "หมดชั่วคราว" สั่งไม่ได้ทั้งหน้าร้านและหน้าลูกค้า
- เบิกสต็อกเกินจำนวนคงเหลือไม่ได้
- เข้าสู่ระบบค้างได้ 12 ชั่วโมง
- รีเซ็ตข้อมูลตัวอย่างไม่ได้อยู่ใน transaction เดียว (เกินขีดจำกัด 500 รายการของ Firestore) ถ้าล้มกลางทางให้กดรีเซ็ตซ้ำ
